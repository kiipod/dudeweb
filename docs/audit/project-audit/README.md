# Project Audit Reports

Эта директория содержит результаты технического аудита проекта.

## Файлы

- `findings.md` — единый реестр всех проблем.
- `project-inventory.md` — архитектура и окружение.
- `pen-design.md` — соответствие Pen-макетам.
- `frontend.md` — frontend и UX.
- `security.md` — безопасность.
- `backend.md` — code review.
- `performance.md` — производительность.
- `tests.md` — тестирование.
- `final-report.md` — итоговый отчёт.

## Правила

1. Каждая подтверждённая проблема имеет уникальный ID.
2. Один дефект — одна запись.
3. Подробный анализ находится в тематическом отчёте.
4. Сводная запись находится в `findings.md`.
5. Статусы обновляются после каждого изменения.
6. Нельзя удалять историю обнаруженных проблем.
7. Исправленные проблемы сохраняются в реестре.
8. Приоритет должен иметь обоснование.
9. Непроверенные предположения не считаются подтверждёнными дефектами.
10. Если проверка невозможна, зафиксировать ограничение.

## ID Prefixes

| Prefix | Area |
|---|---|
| ENV | Environment |
| PEN | Pen Design |
| FE | Frontend |
| SEC | Security |
| BE | Backend |
| PERF | Performance |
| TEST | Tests |

ID не переиспользовать после закрытия проблемы.

## Status Lifecycle

OPEN → IN_PROGRESS → FIXED → VERIFIED

Дополнительные состояния:

- BLOCKED — исправление или проверка заблокированы.
- ACCEPTED_RISK — риск принят после явного согласования.

## Evidence

Доказательство может включать:

- путь к файлу и строки;
- команду и результат;
- воспроизводимый сценарий;
- измеренную метрику;
- ссылку на Pen-компонент;
- скриншот;
- результат теста.

Не включать секреты, токены, пароли или персональные данные.

## Verification

Каждая проблема должна иметь проверяемый критерий устранения.

Нельзя переводить проблему в VERIFIED только на основании
успешного изменения файла.
