# PROJECT_SPEC.md

## Project Overview

Разработать новый публичный сайт и личный кабинет пользователя для сервиса доступа к привычным инструментам для работы и общения.

Сервис не позиционируется как VPN-сервис в интерфейсе, текстах и маркетинговых материалах.

Основная задача проекта:

* привлечение пользователей через простой лендинг;
* регистрация и выдача триального периода;
* управление подпиской;
* отображение состояния аккаунта;
* оплата через ЮKassa;
* получение ссылки на подключение;
* минимальная система поддержки.

# Important Architecture Rule

Перед началом реализации агент обязан выполнить аудит существующего проекта.

Не создавать новые сущности, если они уже существуют.

В первую очередь использовать существующие:

* Models
* Migrations
* Services
* DTO
* Enums
* API Clients
* Repositories
* Policies

Сидеры являются частью бизнес-логики и должны использоваться как источник информации о тарифах, продуктах, промокодах и преимуществах.

## Flow

Пользователь:

1. Выбирает продукт.
2. Вводит промокод.
3. Создается платеж.
4. Редирект в ЮKassa.
5. Возврат на Success Page.
6. Webhook подтверждает платеж.
7. Подписка продлевается.

---

## Subscription Extension

При покупке нового периода:

существующая подписка продлевается.

Пример:

Осталось 70 дней.

Покупка 12 месяцев.

Результат:

70 + 365 дней.
