# Шаг 5 — Интеграция оплаты с Telegram-ботом

## Зависимости

Использовать точки интеграции, найденные в:

`docs/audit/services.md`

## Задачи

- [ ] Найти существующий flow выбора тарифа
- [ ] Найти существующую связь Telegram-пользователя с User
- [ ] Получить User через существующую механику
- [ ] Получить выбранный Product

- [ ] Если бот поддерживает промокоды — получить применённый Promocode
- [ ] Не реализовывать отдельный расчёт скидки внутри Telegram

- [ ] Вызвать `PaymentService::createPayment()`
- [ ] Передать `source = telegram`
- [ ] Передать Telegram return URL / deep-link

- [ ] Получить `confirmation_url`
- [ ] Создать inline-кнопку `Оплатить`
- [ ] Установить URL кнопки равным `confirmation_url`
- [ ] Отправить сообщение пользователю

### Ошибки

- [ ] Перехватить `PaymentCreationException`
- [ ] Залогировать техническую ошибку
- [ ] Не показывать пользователю внутренние детали ошибки
- [ ] Отправить понятное сообщение о невозможности создать платёж
- [ ] Не допускать падения Telegram handler

## Проверка

- [ ] Выбор тарифа создаёт Payment
- [ ] Payment имеет `source = telegram`
- [ ] Payment имеет статус `pending`
- [ ] Пользователь получает кнопку `Оплатить`
- [ ] Кнопка содержит `confirmation_url`
- [ ] Кнопка открывает страницу YooKassa
- [ ] Ошибка YooKassa корректно обрабатывается
- [ ] Telegram handler не содержит дублирующей платёжной логики
