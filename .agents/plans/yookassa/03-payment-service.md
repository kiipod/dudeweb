# Шаг 3 — PaymentService: создание платежа

## Зависимости

Перед реализацией прочитать:

- `docs/audit/models.md`
- `docs/audit/services.md`

Использовать найденную существующую архитектуру.

## Задачи

### PaymentService

- [ ] Найти существующий `PaymentService`
- [ ] Если существует — расширить его
- [ ] Если отсутствует — создать `app/Services/Payment/PaymentService.php`
- [ ] Добавить `YooKassa\Client` через DI

### Расчёт суммы

- [ ] Получить стоимость выбранного `Product`
- [ ] Если передан `Promocode`, использовать существующую механику его проверки
- [ ] Использовать существующую механику расчёта скидки
- [ ] Рассчитать итоговую сумму
- [ ] Не допускать отрицательную итоговую сумму

### Локальный Payment

- [ ] Создать локальную запись `Payment`
- [ ] Связать Payment с User
- [ ] Связать Payment с выбранным Product / Subscription согласно существующей модели
- [ ] Сохранить исходную / итоговую сумму согласно существующей схеме
- [ ] Установить статус `pending`

### Запрос YooKassa

- [ ] Реализовать `createPayment(...)`
- [ ] Сформировать запрос через API SDK версии 3.13.2
- [ ] Передать итоговую сумму
- [ ] Использовать валюту `RUB`
- [ ] Использовать `capture = true`
- [ ] Добавить описание платежа
- [ ] Использовать confirmation типа `redirect`
- [ ] Передать `return_url`

### Metadata

- [ ] Передать локальный `payment_id`
- [ ] Передать `user_id`
- [ ] Передать `product_id`
- [ ] Передать `source`
- [ ] Поддержать `source = web`
- [ ] Поддержать `source = telegram`

### Идемпотентность

- [ ] Создать idempotency key
- [ ] Использовать его при запросе создания платежа
- [ ] Не генерировать новый ключ при повторе одного и того же логического запроса, если существующая архитектура позволяет определить повтор

### Сохранение результата

- [ ] Сохранить `yookassa_payment_id`
- [ ] Сохранить итоговую сумму
- [ ] Сохранить статус
- [ ] Сохранить `confirmation_url`

### Ошибки

- [ ] Проверить существующие payment exceptions
- [ ] Если подходящего исключения нет — создать `PaymentCreationException`
- [ ] Перехватывать ошибки YooKassa SDK
- [ ] Логировать ошибку без credentials
- [ ] Преобразовывать ошибку SDK в `PaymentCreationException`

## Проверка

- [ ] PaymentService разрешается через DI
- [ ] Создание платежа создаёт запись в `payments`
- [ ] Payment имеет статус `pending`
- [ ] Заполнен `yookassa_payment_id`
- [ ] Заполнен `confirmation_url`
- [ ] В metadata передан локальный `payment_id`
- [ ] В metadata передан `source`
- [ ] Промокод корректно влияет на сумму
- [ ] При ошибке SDK выбрасывается `PaymentCreationException`
- [ ] credentials не попадают в логи
