# Аудит и документирование Codex Skills

> **Область:** аудит project-level skills, доступных Codex в текущем проекте.
>
> Исходные skills не изменяются.

## Цель

Провести полный аудит skills, установленных для Codex в текущем проекте,
и сформировать документацию в:

`docs/audit/skills/`

Документация должна позволять без повторного изучения исходных `SKILL.md`
понять:

- какие skills установлены;
- откуда они установлены;
- какие из них доступны Codex;
- для каких задач предназначен каждый skill;
- когда Codex должен использовать каждый skill;
- когда skill использовать не следует;
- какие инструкции и ограничения содержит skill;
- какие дополнительные файлы и ресурсы входят в skill;
- какие skills пересекаются между собой;
- какие skills следует использовать совместно;
- какой skill является более специализированным для конкретной задачи;
- какие возможности skills актуальны для текущего проекта.

## Источник истины

Project-level skills находятся в:

`.agents/skills/`

Основным источником информации о каждом skill является его:

`SKILL.md`

Дополнительными источниками являются файлы самого skill:

- `references/`;
- `examples/`;
- `scripts/`;
- templates;
- документация;
- другие ресурсы.

Фактический список skills необходимо определять по текущему состоянию
репозитория и результату:

    npx skills list

Не считать список skills, существовавший на момент создания плана,
безусловно актуальным.

## Результат

После выполнения плана должна существовать документация:

    docs/audit/skills/
    ├── README.md
    └── <skill-name>.md

Для каждого фактически установленного project skill должен существовать
отдельный документ.

Структура должна соответствовать фактическому состоянию `.agents/skills/`.

Не создавать документацию для отсутствующих skills только потому,
что они упоминались в старых планах или документации.

## Ограничения

В рамках всего плана запрещено:

- изменять `.agents/skills/**`;
- обновлять установленные skills;
- устанавливать новые skills;
- удалять skills;
- изменять код приложения;
- проводить несвязанный рефакторинг;
- изменять `AGENTS.md`;
- менять конфигурацию Codex;
- менять зависимости проекта.

Разрешено создавать и изменять только:

`docs/audit/skills/**`

Если каталог отсутствует — создать его.

Если в рабочем дереве существуют пользовательские изменения вне этой
директории, не изменять и не откатывать их.

## Правила анализа

- полностью читать `SKILL.md`;
- не ограничиваться frontmatter или description;
- не копировать `SKILL.md` целиком;
- документация должна быть аналитическим описанием skill;
- не придумывать возможности, отсутствующие в skill;
- не придумывать правила приоритета;
- не предполагать наличие технологий в проекте без подтверждения;
- version-specific инструкции фиксировать отдельно;
- неоднозначности явно отмечать как требующие проверки.
