# Шаг 2 — Документирование Codex Skills

## Зависимости

Перед началом прочитать:

`docs/audit/skills/inventory.md`

Анализировать только фактически обнаруженные project skills.

## Задачи

Для каждого обнаруженного skill выполнить полный анализ.

### SKILL.md

- [ ] Полностью прочитать `SKILL.md`
- [ ] Не ограничиваться frontmatter
- [ ] Не ограничиваться description
- [ ] Определить назначение
- [ ] Определить область применения
- [ ] Определить поддерживаемые технологии

### Когда использовать

- [ ] Определить конкретные типы задач
- [ ] Определить условия применения
- [ ] Подготовить примеры пользовательских запросов

### Когда не использовать

- [ ] Определить задачи, для которых skill не нужен
- [ ] Определить задачи, где применение skill может привести к неправильному решению
- [ ] Определить ограничения области применения

### Инструкции

Выделить:

- [ ] обязательные инструкции;
- [ ] рекомендации;
- [ ] ограничения;
- [ ] запреты;
- [ ] обязательные проверки;
- [ ] требования к реализации;
- [ ] требования к стилю кода;
- [ ] требования к тестированию;
- [ ] требования к verification.

### Workflow

Определить фактический workflow skill.

Например:

    задача
      ↓
    анализ
      ↓
    выбор подхода
      ↓
    реализация
      ↓
    verification

Не использовать эту схему механически.

Workflow должен основываться на конкретном `SKILL.md`.

### Дополнительные ресурсы

Изучить связанные:

- [ ] reference-файлы;
- [ ] scripts;
- [ ] examples;
- [ ] templates;
- [ ] документацию;
- [ ] другие ресурсы.

Читать ресурс полностью, если без этого невозможно корректно понять
возможности или инструкции skill.

Для каждого ресурса определить:

- назначение;
- когда он используется;
- является ли его использование обязательным;
- какие дополнительные возможности он предоставляет.

### Применимость к проекту

- [ ] Определить, какие части skill применимы к текущему проекту
- [ ] Проверить используемые проектом технологии
- [ ] Проверить version-specific требования
- [ ] Не придумывать отсутствующие технологии

### Пересечения

Для каждого skill предварительно определить:

- [ ] потенциальные пересечения с другими skills;
- [ ] возможное совместное использование;
- [ ] потенциальные конфликты.

Окончательная сравнительная проверка выполняется в следующих задачах.

### Документ

Для каждого skill создать:

`docs/audit/skills/<skill-name>.md`

Использовать структуру:

    # <skill-name>

    ## Общая информация

    ## Когда использовать

    ## Когда не использовать

    ## Возможности

    ## Основные инструкции

    ## Workflow

    ## Дополнительные ресурсы

    ## Применимость к проекту

    ## Пересечения с другими skills

    ## Приоритет инструкций

    ## Ограничения и риски

### Приоритет инструкций

Если инструкции могут пересекаться с:

- `AGENTS.md`;
- другим skill;
- существующей архитектурой;
- документацией проекта;

зафиксировать это.

Не придумывать отсутствующие правила приоритета.

Неоднозначные случаи пометить как:

`Needs review`

## Проверка

Для каждого документа:

- [ ] информация основана на фактическом `SKILL.md`
- [ ] `SKILL.md` полностью изучен
- [ ] дополнительные необходимые ресурсы изучены
- [ ] нет выдуманных возможностей
- [ ] указаны реальные пути
- [ ] описано назначение
- [ ] описано, когда использовать
- [ ] описано, когда не использовать
- [ ] описаны ограничения
- [ ] описан workflow
- [ ] указаны version-specific требования
- [ ] описана применимость к проекту
- [ ] описаны известные пересечения
- [ ] исходный `SKILL.md` не скопирован целиком

Также:

- [ ] Для каждого skill из `inventory.md` существует отдельный документ
- [ ] `.agents/skills/**` не изменён
- [ ] Код приложения не изменён
