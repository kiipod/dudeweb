# Шаг 2 — Документирование Codex Skills

## Зависимости

Перед началом прочитать:

`docs/audit/skills/inventory.md`

Анализировать только фактически обнаруженные project skills.

## Задачи

Для каждого обнаруженного skill выполнить полный анализ.

### SKILL.md

- [x] Полностью прочитать `SKILL.md`
- [x] Не ограничиваться frontmatter
- [x] Не ограничиваться description
- [x] Определить назначение
- [x] Определить область применения
- [x] Определить поддерживаемые технологии

### Когда использовать

- [x] Определить конкретные типы задач
- [x] Определить условия применения
- [x] Подготовить примеры пользовательских запросов

### Когда не использовать

- [x] Определить задачи, для которых skill не нужен
- [x] Определить задачи, где применение skill может привести к неправильному решению
- [x] Определить ограничения области применения

### Инструкции

Выделить:

- [x] обязательные инструкции;
- [x] рекомендации;
- [x] ограничения;
- [x] запреты;
- [x] обязательные проверки;
- [x] требования к реализации;
- [x] требования к стилю кода;
- [x] требования к тестированию;
- [x] требования к verification.

### Workflow

Определить фактический workflow skill.

Например:

    задача
      ↓
    анализ
      ↓
    выбор подхода
      ↓
    реализация
      ↓
    verification

Не использовать эту схему механически.

Workflow должен основываться на конкретном `SKILL.md`.

### Дополнительные ресурсы

Изучить связанные:

- [x] reference-файлы;
- [x] scripts;
- [x] examples;
- [x] templates;
- [x] документацию;
- [x] другие ресурсы.

Читать ресурс полностью, если без этого невозможно корректно понять
возможности или инструкции skill.

Для каждого ресурса определить:

- назначение;
- когда он используется;
- является ли его использование обязательным;
- какие дополнительные возможности он предоставляет.

### Применимость к проекту

- [x] Определить, какие части skill применимы к текущему проекту
- [x] Проверить используемые проектом технологии
- [x] Проверить version-specific требования
- [x] Не придумывать отсутствующие технологии

### Пересечения

Для каждого skill предварительно определить:

- [x] потенциальные пересечения с другими skills;
- [x] возможное совместное использование;
- [x] потенциальные конфликты.

Окончательная сравнительная проверка выполняется в следующих задачах.

### Документ

Для каждого skill создать:

`docs/audit/skills/<skill-name>.md`

Использовать структуру:

    # <skill-name>

    ## Общая информация

    ## Когда использовать

    ## Когда не использовать

    ## Возможности

    ## Основные инструкции

    ## Workflow

    ## Дополнительные ресурсы

    ## Применимость к проекту

    ## Пересечения с другими skills

    ## Приоритет инструкций

    ## Ограничения и риски

### Приоритет инструкций

Если инструкции могут пересекаться с:

- `AGENTS.md`;
- другим skill;
- существующей архитектурой;
- документацией проекта;

зафиксировать это.

Не придумывать отсутствующие правила приоритета.

Неоднозначные случаи пометить как:

`Needs review`

Для каждого документа:

- [x] информация основана на фактическом `SKILL.md`
- [x] `SKILL.md` полностью изучен
- [x] дополнительные необходимые ресурсы изучены
- [x] нет выдуманных возможностей
- [x] указаны реальные пути
- [x] описано назначение
- [x] описано, когда использовать
- [x] описано, когда не использовать
- [x] описаны ограничения
- [x] описан workflow
- [x] указаны version-specific требования
- [x] описана применимость к проекту
- [x] описаны известные пересечения
- [x] исходный `SKILL.md` не скопирован целиком

Также:

- [x] Для каждого skill из `inventory.md` существует отдельный документ
- [x] `.agents/skills/**` не изменён
- [x] Код приложения не изменён
