# Шаг 4 — Анализ Frontend Skills

## Зависимости

Анализировать только фактически установленные frontend skills.

Ожидаемые кандидаты:

- `frontend-design`
- `vue-best-practices`
- `nuxt-ui`
- `tailwind-4-docs`
- `tailwind-css-patterns`

Этот список не считать источником истины.

Фактический список брать из:

`docs/audit/skills/inventory.md`

## Задачи

### Области ответственности

На основании фактического содержимого skills определить ответственность
каждого.

Проверить гипотезу:

    Design / UX
        ↓
    frontend-design

    Vue architecture
        ↓
    vue-best-practices

    Nuxt UI components
        ↓
    nuxt-ui

    Tailwind 4 API
        ↓
    tailwind-4-docs

    Tailwind implementation patterns
        ↓
    tailwind-css-patterns

Не принимать эту схему автоматически.

- [ ] Подтвердить каждую область содержимым `SKILL.md`
- [ ] Скорректировать схему при необходимости

### Пересечения

- [ ] Найти пересечения между skills
- [ ] Найти дублирующиеся инструкции
- [ ] Найти потенциальные противоречия
- [ ] Найти complementary-инструкции

### Специализация

Для каждого типа frontend-задачи определить наиболее специализированный skill.

Проверить:

- [ ] UI/UX design
- [ ] Vue architecture
- [ ] Vue components
- [ ] Nuxt UI
- [ ] Tailwind 4 API
- [ ] Tailwind implementation patterns
- [ ] полноценная frontend feature

Добавлять только категории, подтверждённые содержимым skills.

### Совместное использование

Определить фактически обоснованные комбинации.

Например, проверить:

    Vue + Tailwind component

    Nuxt UI page

    Полная frontend feature

Для каждой комбинации:

- [ ] определить необходимые skills;
- [ ] определить ответственность каждого;
- [ ] определить возможные конфликты;
- [ ] определить, требуется ли совместное использование вообще.

Не переносить предполагаемые комбинации механически.

### Текущий проект

- [ ] Проверить фактический frontend stack
- [ ] Определить применимость каждого skill
- [ ] Проверить version-specific требования
- [ ] Не считать skill полезным только потому, что он установлен

### Документация

Обновить соответствующие:

`docs/audit/skills/<skill-name>.md`

## Проверка

- [ ] Все фактически установленные frontend skills проанализированы
- [ ] Зоны ответственности определены
- [ ] Исходная гипотеза подтверждена или скорректирована
- [ ] Пересечения описаны
- [ ] Потенциальные конфликты описаны
- [ ] Специализированные области определены
- [ ] Совместное использование описано
- [ ] Применимость к текущему проекту проверена
- [ ] Документация skills обновлена
