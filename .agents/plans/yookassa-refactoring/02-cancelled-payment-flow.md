# Шаг 2 — Доработка flow отменённых платежей

## Зависимости

Перед началом прочитать:

- `docs/audit/yookassa-refactoring.md`
- `docs/yookassa/declined-payments.md`
- `docs/yookassa/test-payment.md`

## Цель

При `payment.canceled`:

1. определить причину отмены;
2. показать пользователю понятное сообщение;
3. не использовать `confirmation_url` отменённого Payment;
4. предоставить корректный сценарий повторной оплаты;
5. при повторной оплате использовать новый YooKassa Payment и новый
   `confirmation_url`.

## cancellation_details

При обработке отменённого платежа получить:

- [ ] `cancellation_details.party`
- [ ] `cancellation_details.reason`

Не определять причину по тексту ошибки.

Не определять причину по HTTP-коду.

Использовать структурированные `cancellation_details`.

## Модель причин отмены

На основании:

`docs/yookassa/declined-payments.md`

определить внутреннее представление причины отмены.

Проверить существующие Enum/value objects проекта.

Если подходящей структуры нет:

- [ ] определить необходимость отдельного Enum;
- [ ] определить необходимость mapper/resolver;
- [ ] не помещать большой `match` причин непосредственно в Telegram handler.

Для каждой поддерживаемой причины определить:

- `party`;
- `reason`;
- пользовательское сообщение;
- допустимость повторной попытки;
- рекомендуемое действие.

## Пользовательские сообщения

Для каждого описанного в документации сценария:

- [ ] использовать соответствующее сообщение;
- [ ] не показывать технические значения `reason`;
- [ ] не показывать внутренние ошибки;
- [ ] дать пользователю понятное дальнейшее действие.

Добавить fallback для неизвестного `reason`.

Fallback не должен приводить к exception.

## Старый confirmation_url

После `payment.canceled`:

- [ ] не использовать старый `confirmation_url`;
- [ ] не отправлять его пользователю;
- [ ] не использовать его для кнопки повторной оплаты.

Старый URL может оставаться в Payment для истории, если поле используется
для хранения данных платежа.

Не очищать его только ради предотвращения повторного использования.

## Повторная оплата

Проверить существующий механизм создания Payment.

При повторной попытке:

    canceled Payment
          ↓
    retry payment action
          ↓
    createPayment(...)
          ↓
    новый локальный Payment
          ↓
    новый YooKassa Payment
          ↓
    новый yookassa_payment_id
          ↓
    новый confirmation_url

- [ ] Создаётся новый локальный Payment
- [ ] Создаётся новый YooKassa Payment
- [ ] Новый Payment имеет собственный `yookassa_payment_id`
- [ ] Новый Payment имеет новый `confirmation_url`
- [ ] Новый Payment имеет статус `pending`
- [ ] Новый Payment связан с тем же User
- [ ] Используется правильный Product
- [ ] Promocode обрабатывается существующей бизнес-логикой
- [ ] `source` сохраняется корректно

## Telegram

После отмены:

- [ ] отправить сообщение согласно `cancellation_details`;
- [ ] предоставить пользователю возможность повторной оплаты, если это допустимо;
- [ ] не использовать URL отменённого платежа.

Если новый Payment создаётся сразу в рамках существующего flow:

- [ ] кнопка `Оплатить` содержит новый `confirmation_url`.

Если новый Payment создаётся только после действия пользователя:

- [ ] callback/action создаёт новый Payment;
- [ ] после создания пользователю отправляется новая кнопка оплаты.

Выбрать вариант, наиболее соответствующий существующей архитектуре.

Не создавать отдельную дублирующую платёжную логику в Telegram handler.

## Ошибка повторного создания

Если новый Payment создать не удалось:

- [ ] старый `confirmation_url` не использовать;
- [ ] показать безопасное пользовательское сообщение;
- [ ] техническую ошибку записать в лог;
- [ ] credentials и чувствительные данные не логировать.

## Идемпотентность

Повторная доставка одного `payment.canceled`:

- [ ] не должна создавать бесконечное количество новых Payment;
- [ ] не должна создавать несколько retry-ссылок без необходимости;
- [ ] не должна повторно выполнять бизнес-side-effects.

Проверить существующий механизм идемпотентности.

При необходимости адаптировать его.
