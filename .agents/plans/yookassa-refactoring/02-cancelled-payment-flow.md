# Шаг 2 — Доработка flow отменённых платежей

## Зависимости

Перед началом прочитать:

## Цель

При `payment.canceled`:

1. определить причину отмены;
2. показать пользователю понятное сообщение;
3. не использовать `confirmation_url` отменённого Payment;
4. предоставить корректный сценарий повторной оплаты;
5. при повторной оплате использовать новый YooKassa Payment и новый
   `confirmation_url`.

## cancellation_details

При обработке отменённого платежа получить:

- [x] `cancellation_details.party`
- [x] `cancellation_details.reason`

Не определять причину по тексту ошибки.

Не определять причину по HTTP-коду.

Использовать структурированные `cancellation_details`.

`docs/yookassa/declined-payments.md`

Проверить существующие Enum/value objects проекта.

Если подходящей структуры нет:

- [x] определить необходимость отдельного Enum;

- пользовательское сообщение;
- допустимость повторной попытки;
- рекомендуемое действие.

## Старый confirmation_url

После `payment.canceled`:

- [x] не использовать старый `confirmation_url`;
- [x] не отправлять его пользователю;
- [x] не использовать его для кнопки повторной оплаты.

Старый URL может оставаться в Payment для истории, если поле используется
для хранения данных платежа.

Не очищать его только ради предотвращения повторного использования.

          ↓
    новый YooKassa Payment

    новый yookassa_payment_id
