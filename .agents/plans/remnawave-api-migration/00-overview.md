# Миграция Remnawave API

> **Область:** сверка существующей интеграции Remnawave с API новой major-версии панели и адаптация DTO, Handler и мест их использования.
>
> Актуальная OpenAPI-документация:
>
> `docs/remnawave/api-1.json`

## Источник истины

Файл:

`docs/remnawave/api-1.json`

является источником истины для:

- endpoint;
- HTTP-методов;
- path/query/body параметров;
- request schema;
- response schema;
- обязательных полей;
- типов данных;
- nullable-полей;
- enum;
- структуры ошибок.

Существующий код Remnawave расположен в:

`app/Remnawave/`

Существующий код необходимо адаптировать под новый API, а не подгонять новую документацию под старую реализацию.

## Правила

- не изменять API-контракт, описанный в `docs/remnawave/api-1.json`;
- не придумывать отсутствующие в документации поля;
- не сохранять устаревшие поля только ради совместимости, если они больше не существуют в API;
- перед изменением DTO определить все места его использования;
- перед изменением Handler определить все места его использования;
- переиспользовать существующую архитектуру `app/Remnawave/`;
- не выполнять несвязанный рефакторинг;
- не изменять бизнес-логику за пределами изменений, необходимых для нового API;
- если endpoint удалён без прямой замены — зафиксировать это отдельно и не придумывать альтернативный endpoint;
- если назначение нового endpoint неоднозначно — остановить соответствующую миграцию и зафиксировать расхождение;
- каждый шаг завершается разделом **Проверка**;
- Commit выполняется только после успешного прохождения проверки.

## Результат

После выполнения плана:

- существующие DTO соответствуют новой OpenAPI schema;
- Handler используют актуальные endpoint;
- Handler используют актуальные HTTP-методы;
- request соответствуют новой структуре;
- response соответствуют новой структуре;
- удалены обращения к полям старого API;
- все места использования адаптированы;
- существующие сценарии Remnawave работают через новый API.

## Порядок выполнения

Шаги выполняются строго последовательно.

После каждого шага:

1. выполнить все пункты раздела **Проверка**;
2. отметить выполненные микрозадачи;
3. обновить статус в этом файле;
4. выполнить указанный Commit;
5. только после этого переходить к следующему шагу.
