# Шаг 1 — Сверка существующей интеграции с новым Remnawave API

На этом шаге production-код не изменяется.

Цель — определить все расхождения между существующей реализацией и новой документацией.

## Источник истины

`docs/remnawave/api-1.json`

### Сверка DTO

Для каждого существующего DTO:

- [ ] найти соответствующую schema в `api-1.json`;
- [ ] сравнить список полей;
- [ ] найти добавленные поля;
- [ ] найти удалённые поля;
- [ ] найти переименованные поля;
- [ ] найти изменения типов;
- [ ] найти изменения nullable;

- [ ] найти изменения вложенных объектов;
- [ ] найти изменения массивов;
- [ ] найти изменения enum.

### Классификация изменений

Для каждого Handler и DTO присвоить статус:

- `UNCHANGED` — изменение не требуется;
- `MODIFIED` — контракт изменился;
- `REMOVED` — контракт удалён;
- `REPLACED` — существует новый контракт вместо старого;
- `UNKNOWN` — однозначное соответствие определить невозможно.
