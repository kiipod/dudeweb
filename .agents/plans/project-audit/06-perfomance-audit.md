# Шаг 6 — Performance Audit

## Цель

Выявить реальные проблемы производительности frontend,
backend, БД и внешних интеграций.

Оптимизацию выполнять только после измерений или
подтверждения конкретного неэффективного алгоритма.

## Baseline

- [ ] Определить доступные средства измерения.
- [ ] Зафиксировать конфигурацию окружения.
- [ ] Определить критические пользовательские сценарии.
- [ ] Зафиксировать исходные метрики.
- [ ] Отделить локальные измерения от production-показателей.

Не выполнять нагрузочные тесты на production без разрешения.

## Database

- [ ] Найти N+1 queries.
- [ ] Проверить eager loading.
- [ ] Проверить тяжёлые JOIN.
- [ ] Проверить запросы без нужных индексов.
- [ ] Проверить лишние SELECT *.
- [ ] Проверить pagination.
- [ ] Проверить повторные запросы.
- [ ] Проверить планы выполнения тяжёлых запросов.

## Backend

- [ ] Проверить синхронные внешние HTTP-вызовы.
- [ ] Проверить timeout.
- [ ] Проверить retry policy.
- [ ] Проверить Queue/Jobs.
- [ ] Проверить Scheduler.
- [ ] Проверить кеширование.
- [ ] Проверить повторные вычисления.
- [ ] Проверить неэффективные циклы.
- [ ] Проверить потребление памяти.

## Frontend

- [ ] Проверить размер JS bundle.
- [ ] Проверить размер CSS bundle.
- [ ] Проверить code splitting.
- [ ] Проверить lazy loading.
- [ ] Проверить загрузку изображений.
- [ ] Проверить шрифты.
- [ ] Проверить лишние API-запросы.
- [ ] Проверить повторные рендеры.
- [ ] Проверить тяжёлые анимации.
- [ ] Проверить scroll performance.

## Web Vitals

Если доступны браузерные инструменты:

- [ ] LCP.
- [ ] INP.
- [ ] CLS.
- [ ] FCP.
- [ ] TTFB.

Для каждой метрики указать условия измерения.

## External Integrations

- [ ] Проверить количество Remnawave API requests.
- [ ] Проверить YooKassa API requests.
- [ ] Проверить Telegram API requests.
- [ ] Проверить batch processing.
- [ ] Проверить обработку rate limits.
- [ ] Проверить повторные вызовы при ошибках.

## Отчёт

Создать:

docs/audit/project-audit/performance.md

Для каждой измеренной проблемы указать:

| Scenario | Metric | Baseline | Target | Finding |
|---|---|---|---|---|

Target задавать на основании требований или согласованной цели.

Не придумывать численные показатели.

## Findings

Использовать префикс PERF.

Указывать измерения и условия воспроизведения.

## Проверка

- [ ] Доступные метрики собраны.
- [ ] Критические сценарии проверены.
- [ ] Backend bottlenecks проанализированы.
- [ ] Frontend bottlenecks проанализированы.
- [ ] Database queries проверены.
- [ ] Findings обновлены.
- [ ] Production-код не изменён.
