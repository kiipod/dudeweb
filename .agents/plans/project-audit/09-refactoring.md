# Шаг 9 — Refactoring

## Цель

Улучшить качество кода, производительность,
архитектуру и соответствие Pen-макетам.

Исправлять согласованные проблемы P2/P3
и подтверждённый технический долг.

## Условия начала

- [ ] Критические проблемы обработаны.
- [ ] Scope рефакторинга согласован.
- [ ] Существующие тесты проверены.
- [ ] Доступны baseline-метрики, если требуется оптимизация.

## Подготовка

- [ ] Прочитать findings.md.
- [ ] Прочитать backend.md.
- [ ] Прочитать frontend.md.
- [ ] Прочитать pen-design.md.
- [ ] Прочитать performance.md.
- [ ] Определить зависимости между изменениями.
- [ ] Разбить рефакторинг на независимые логические части.

## Backend Refactoring

Для подтверждённых проблем:

- [ ] Уменьшить избыточные ответственности.
- [ ] Декомпозировать сложные методы.
- [ ] Устранить дублирование.
- [ ] Упростить условные конструкции.
- [ ] Удалить доказанно неиспользуемый код.
- [ ] Упростить зависимости.
- [ ] Улучшить error handling.
- [ ] Проверить транзакции.
- [ ] Сохранить API-контракты.

Не создавать лишние Service/Action/Interface.

## Frontend Refactoring

- [ ] Устранить дублирование компонентов.
- [ ] Упростить состояние.
- [ ] Убрать ненужные watchers/effects.
- [ ] Упростить формы.
- [ ] Устранить CSS duplication.
- [ ] Исправить подтверждённые responsive issues.
- [ ] Исправить подтверждённые UX issues.
- [ ] Сохранить интерактивность.

## Pen Design Fixes

Для каждого PEN finding:

- [ ] Проверить соответствующий макет.
- [ ] Исправить подтверждённое расхождение.
- [ ] Проверить mobile viewport.
- [ ] Проверить desktop viewport.
- [ ] Проверить интерактивные состояния.
- [ ] Проверить отсутствие визуальных регрессий.

Не изменять дизайн произвольно.

## Performance Optimization

- [ ] Исправить подтверждённые N+1.
- [ ] Оптимизировать тяжёлые запросы.
- [ ] Уменьшить лишние API-вызовы.
- [ ] Оптимизировать frontend bundles, если необходимо.
- [ ] Оптимизировать изображения.
- [ ] Оптимизировать вычисления.
- [ ] Проверить кеширование.

После изменения сравнить показатели с baseline.

## Database Refactoring

- [ ] Проверить необходимость schema changes.
- [ ] Проверить все references.
- [ ] Проверить исторические данные.
- [ ] Проверить rollback.
- [ ] Проверить миграции на тестовой БД.

Не удалять столбцы только потому,
что они выглядят избыточными.

## Testing

Для каждого изменения:

- [ ] Добавить или обновить тесты.
- [ ] Запустить связанные тесты.
- [ ] Проверить исходный finding.
- [ ] Проверить регрессии.
- [ ] Обновить findings.md.

## Documentation

Для каждого исправления указать:

- Finding ID;
- изменённые файлы;
- принятое решение;
- результаты тестов;
- метрики до/после, если применимо;
- commit.

## Проверка

- [ ] Согласованные проблемы обработаны.
- [ ] Не создана лишняя архитектурная сложность.
- [ ] Бизнес-логика сохранена.
- [ ] API-контракты сохранены либо изменения согласованы.
- [ ] Performance regression отсутствует по доступным измерениям.
- [ ] Pen fixes проверены.
- [ ] Findings обновлены.

## Commit

Использовать отдельные commits по задачам:

refactor: resolve BE-...
perf: resolve PERF-...
fix: resolve PEN-...
