# Шаг 4 — Security Audit

## Цель

Выявить уязвимости приложения, ошибки авторизации,
небезопасные конфигурации и риски внешних интеграций.

Все активные проверки выполнять только в разрешённом
локальном или тестовом окружении.

## Authentication

- [ ] Проверить login/logout.
- [ ] Проверить session management.
- [ ] Проверить срок действия токенов.
- [ ] Проверить password hashing.
- [ ] Проверить session fixation.
- [ ] Проверить cookie flags.
- [ ] Проверить защиту от brute force.
- [ ] Проверить rate limiting.

## Authorization

- [ ] Проверить middleware.
- [ ] Проверить policies/gates.
- [ ] Проверить разграничение ролей.
- [ ] Проверить доступ к чужим ресурсам.
- [ ] Проверить IDOR.
- [ ] Проверить ownership checks.
- [ ] Проверить защищённость административных маршрутов.

Особенно проверить операции с:

- подписками;
- платежами;
- устройствами;
- профилем пользователя;
- промокодами;
- реферальными данными.

## Input Validation

- [ ] Проверить Request validation.
- [ ] Проверить SQL injection.
- [ ] Проверить XSS.
- [ ] Проверить CSRF.
- [ ] Проверить SSRF.
- [ ] Проверить mass assignment.
- [ ] Проверить path traversal.
- [ ] Проверить небезопасную десериализацию.
- [ ] Проверить загрузку файлов.

## Payments

Если используется YooKassa:

- [ ] Проверить создание платежей.
- [ ] Проверить серверный расчёт суммы.
- [ ] Проверить привязку платежа к пользователю.
- [ ] Проверить обработку webhook.
- [ ] Проверить проверку подлинности уведомлений.
- [ ] Проверить повторную доставку webhook.
- [ ] Проверить идемпотентность.
- [ ] Проверить защиту от повторного начисления.
- [ ] Проверить отменённые платежи.
- [ ] Проверить отсутствие доверия к return URL как подтверждению оплаты.

## Telegram

- [ ] Проверить авторизацию callback.
- [ ] Проверить ownership пользовательских операций.
- [ ] Проверить обработку deep-link.
- [ ] Проверить защиту от self-referral.
- [ ] Проверить повторную обработку callback.
- [ ] Проверить хранение bot token.
- [ ] Проверить безопасное логирование.

## Remnawave

- [ ] Проверить хранение API credentials.
- [ ] Проверить авторизацию запросов.
- [ ] Проверить обработку ошибок API.
- [ ] Проверить доступ к чужим подпискам.
- [ ] Проверить изменение статусов.
- [ ] Проверить управление устройствами.
- [ ] Проверить защиту от некорректных внешних данных.

## Configuration

- [ ] Проверить APP_DEBUG.
- [ ] Проверить production error output.
- [ ] Проверить CORS.
- [ ] Проверить HTTPS.
- [ ] Проверить security headers.
- [ ] Проверить доступность служебных файлов.
- [ ] Проверить .gitignore.
- [ ] Проверить секреты в tracked files.
- [ ] Проверить логирование персональных данных.

## Dependencies

Выполнить доступные проверки:

- composer audit
- npm audit

Дополнительно проверить:

- [ ] Поддерживаемость зависимостей.
- [ ] Известные уязвимости.
- [ ] Риски обновления.
- [ ] Прямые и транзитивные зависимости.

Не выполнять автоматическое массовое обновление зависимостей.

## Findings

Использовать префикс SEC.

Для каждой уязвимости указать:

- затронутый компонент;
- необходимые условия эксплуатации;
- возможное воздействие;
- воспроизводимое безопасное доказательство;
- приоритет;
- способ устранения.

Не сохранять в отчётах реальные секреты или эксплуатационные данные.
