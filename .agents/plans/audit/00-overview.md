# Аудит проекта

> **Область:** исследование существующей архитектуры проекта.
>
> На этом этапе production-код не изменяется.

## Правила

- существующий код — источник истины;
- не создавать новые сущности;
- не выполнять рефакторинг;
- не исправлять найденные проблемы;
- найденные особенности и проблемы фиксировать в документации;
- все API-методы и данные Remnawave находятся в `app/Remnawave/`.

## Порядок выполнения

Шаги выполняются последовательно.

После каждого шага:

1. выполнить блок **Проверка**;
2. отметить выполненные микрозадачи;
3. обновить статус шага в этом файле;
4. выполнить указанный Commit.

Не переходить к следующему шагу, пока текущий не прошёл проверку.
