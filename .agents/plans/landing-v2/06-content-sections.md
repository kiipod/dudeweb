# Шаг 6 — Content Sections

## Цель

Реализовать все контентные секции Landing V2,
кроме Header, Hero, News и Footer/Final CTA,
которые выполняются отдельными задачами.

## Зависимости

- docs/landing-v2/design-inventory.md
- docs/landing-v2/implementation-map.md

## Section Inventory

- [ ] Получить полный список секций из design-inventory.md.
- [ ] Исключить уже реализованные секции.
- [ ] Определить порядок реализации.
- [ ] Определить общие UI patterns.
- [ ] Определить необходимые assets.

Не добавлять секции, отсутствующие в актуальном макете.

## Для каждой секции

### Structure

- [ ] Реализовать структуру.
- [ ] Перенести заголовки.
- [ ] Перенести описания.
- [ ] Перенести карточки.
- [ ] Перенести изображения.
- [ ] Перенести кнопки и ссылки.
- [ ] Сохранить порядок элементов.

### Design

- [ ] Typography.
- [ ] Spacing.
- [ ] Colors.
- [ ] Layout.
- [ ] Borders.
- [ ] Background.
- [ ] Responsive variants.

### Functionality

- [ ] Реализовать предусмотренные действия.
- [ ] Использовать существующие бизнес-механизмы.
- [ ] Не создавать дублирующую backend-логику.
- [ ] Проверить ссылки и callbacks.

### Components

- [ ] Выделять повторно используемые компоненты при необходимости.
- [ ] Не создавать отдельный компонент для каждого декоративного элемента.
- [ ] Избегать дублирования.
- [ ] Сохранить понятную структуру.

## Pricing

Если в V2 есть тарифный блок:

- [ ] Перенести дизайн из Pen.
- [ ] Проверить текущий источник тарифов.
- [ ] Переиспользовать существующую бизнес-логику, если она нужна.
- [ ] Не дублировать расчёт стоимости.
- [ ] Не изменять правила скидок.
- [ ] Проверить CTA оплаты.

Не считать тарифные значения из макета актуальными
backend-данными без проверки.
