# Landing V2 — Перенос макета Pen

## Цель

Реализовать новую версию публичного лендинга на основании
существующих страниц Landing V2 в Pen.

Новый лендинг должен быть доступен по адресу:

/landing

Существующая главная страница:

/

должна сохранить текущий дизайн, функциональность и поведение.

## Источники истины

1. Новые страницы Landing V2 в Pen.
2. Существующая архитектура проекта.
3. Текущая дизайн-система, если она совместима с V2.
4. Существующие маршруты и бизнес-функциональность.

Не придумывать секции, тексты, анимации и функциональность,
которые не предусмотрены макетом или требованиями.

## Основные требования

### Routing

- / — существующая главная страница.
- /landing — новый Landing V2.

Не переназначать маршрут / на новый лендинг.

### Design

- Перенести актуальный Landing V2 из Pen.
- Сохранить визуальную структуру.
- Сохранить тексты.
- Сохранить типографику и цветовую палитру.
- Сохранить предусмотренные интерактивные состояния.
- Реализовать mobile-first.

### News

Блок новостей реализовать статически.

Запрещено создавать для него:

- database tables;
- migrations;
- Eloquent models;
- repositories;
- API endpoints;
- административный CRUD;
- интеграцию с CMS;
- scheduler;
- внешние источники новостей.

Данные хранить локально в frontend.

### Isolation

Landing V2 не должен изменять внешний вид и поведение
существующей главной страницы.

Не менять общие компоненты без анализа влияния на другие страницы.

## Технические правила

- Использовать фактический frontend stack проекта.
- Переиспользовать существующие зависимости.
- Не устанавливать UI-библиотеки без необходимости.
- Не создавать дублирующие глобальные стили.
- Не использовать inline styles без обоснования.
- Не добавлять неиспользуемые компоненты.
- Не менять существующую бизнес-логику.
- Не проводить несвязанный рефакторинг.
- Не добавлять backend-функциональность для новостей.
